\subsection{Storage Sensing and Risk Rule}
\label{sec:method-storage}

\draftfor{Claude draft, 22 Oct 2026. Rewrite in the authors' words. The node in Fig.~\ref{fig:hardware} is not
assembled yet (kit not bought); everything marked built has been compiled and tested, and the rule has been run
only on simulated readings (Sect.~\ref{sec:results-storage}).}

Basmati paddy is stored on the farm in jute bags until it is sold, often for months. To give the selling plan a
signal about storage conditions, we place one probe inside a bag and read the air between the kernels.
Figure~\ref{fig:hardware} shows the path from that probe to the planner.

\paragraph{Node.} The probe is a protected SHT30 humidity and temperature sensor whose typical tolerance is
$\pm2$\,\%RH and $\pm0.2$\,$^\circ$C~\cite{sht3x}. It is connected over I$^2$C (GPIO~21 and 22, 4.7\,k$\Omega$
pull-ups) to an ESP32-WROOM-32 board~\cite{esp32} that stays outside the bag. Every 5 minutes the firmware takes one
single-shot, high-repeatability reading and checks the CRC byte that the sensor sends with each value. A failed read
is sent as an empty value with its error code, never as zero. Each message carries the device identifier, a random
boot identifier and a sequence number; together these identify a reading uniquely, so a repeated delivery can be
recognised. Readings taken before the clock is synchronised get their time later from the board's uptime, or stay
without a time.

\paragraph{Transport and storage.} The node sends JSON messages over the farm's phone hotspot to an MQTT broker on
the FPO's laptop, using TLS with a separate password and topic permission for each device. A reading stays in a
288-sample buffer in the board's memory (24\,h) until the server reports that it has stored it; a broker
acknowledgement alone is not enough. The server checks each message against a JSON schema, stores it once per
(device, boot, sequence) and then sends the acknowledgement. The buffer is in RAM, so a power cut loses the readings
that were not yet sent. The same firmware runs in the Wokwi simulator~\cite{wokwi}; Wokwi has no SHT3x part, so we
wrote a small custom chip that answers the sensor's I$^2$C commands with the same CRC, which lets anyone run the node
without hardware. Readings from this twin are labelled synthetic.

\paragraph{Storage rule (STORAGE-DEMO-0.1).} Grain exchanges moisture with the air between its kernels until the
two are in equilibrium; that air's relative humidity divided by 100 is the grain's water activity $a_w$. The storage
limits in the literature are stated on this scale: storage fungi need a relative humidity of at least 65\,\% and grow
between about 10 and 40\,$^\circ$C~\cite{gwinner1996}, and grain kept in equilibrium with air below 65--70\,\% RH
degrades slowly~\cite{delucia1994}. The rule therefore takes the median
relative humidity and temperature of the last 24\,h and assigns LOW for $a_w<0.65$, MEDIUM for $0.65\le a_w<0.70$ and
HIGH for $a_w\ge0.70$. The level rises as soon as the median crosses a limit, but falls only after the median has
stayed at least 2 points below the limit for 48\,h, so that a reading near 65\,\% does not switch back and forth. Grain
below 10\,$^\circ$C is moved one level down; grain at 25\,$^\circ$C or warmer with $a_w\ge0.60$ is moved from LOW to
MEDIUM. A separate note says whether the temperature favours insects ($\ge25$\,$^\circ$C), slows them (15--25) or
stops most activity ($<15$); it does not change the level.

The rule returns UNKNOWN, with the reasons, when the probe is registered as hanging in shed air, during the first 6\,h
after the probe is pushed into a bag, when the newest usable reading is older than 15 minutes, or when fewer than
75\,\% of the expected readings of the last 24\,h are usable. The same thresholds apply to basmati paddy and to wheat,
because they are limits on water activity rather than on a crop's moisture content. The rule does not report moisture
content, which would need sorption-isotherm constants that we could not verify, and it does not detect spoilage. It
says whether the air in one bag favours mould and insects. The rule is part of the shared core package that the
product also uses, and is covered by unit, boundary and property tests.
